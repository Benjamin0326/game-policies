### Google Play와 광고를 켜기 위한 조건

- 13세 이상 대상 선언은 Play의 13–15세, 16–17세, 18세 이상 그룹을 실제 게임·등록정보와 대조해 입력한다. 13–15세와 16–17세도 일부 지역에서 아동 범주에 포함될 수 있다. 혼합 대상에 Families가 적용되면 아동·연령 미확인 이용자의 AAID 등 지정 식별자 전송을 차단한다. 아동 대상 사용이 승인되지 않은 API·SDK는 중립적인 연령 확인 뒤에 두거나 아동 데이터가 수집되지 않도록 구현한다. 광고를 제공한다면 중립적인 연령 확인을 적용하고, 아동·연령 미확인 이용자에게는 자체 인증된 정확한 SDK 버전으로 연령에 맞는 광고를 제공하며 맞춤형 광고와 리마케팅을 금지한다. 게임 이용을 방해하는 보상형 광고 등은 5초가 지나면 닫을 수 있어야 한다. 공개 인증 목록의 Google AdMob 항목은 `com.google.android.gms:play-services-ads`를 가리킨다. 이 항목으로 Next-Gen `ads-mobile-sdk:1.6.0`의 인증을 확인할 수 없으므로 적용 시 버전별 자격을 별도로 확인한다. | GMA의 IP, 식별자, 활동 및 진단 | SDK 포함 및 현재 앱 주도 호출 비활성, Google이 공시한 가능한 처리. 실제 확인된 항목·목적·수신자, 사용자 선택, 보안, 보관·삭제, 외부 제공과 이전 조건을 반영한다. | 후보 분류는 IP 기반 **대략적 위치**(실제 추정에 쓰일 경우), **기기 또는 기타 ID**(AD_ID·앱 세트 ID 등), **앱 활동 → 앱 상호작용**, **앱 정보 및 성능 → 진단**이다. 크래시 로그·기타 성능 및 계정 관련 ID의 세부 분류는 실제 필드와 사용에 따라 추가 검토한다. 최신 공시의 목적은 광고 또는 마케팅, 분석, 부정사용 방지·보안·규정 준수에 대응시켜 실제 목적만 선택한다. |
| UMP 동의 상태와 선택 | SDK의 역할과 앱 주도 갱신 비활성을 설명한다. 동의 정보가 실제로 처리되면 항목, 저장 위치, 수신자 및 철회 경로를 확인해 반영한다. | UMP 패키징만으로 수집을 확정할 수 없다. 기기 밖으로 전송되는 필드와 수신처가 확인되면 해당 데이터 유형과 목적을 분류한다. 로컬 동의 상태는 동일하게 앱 밖 전송 여부를 기준으로 판단한다. |

- Data safety는 패키지 단위로 비공개 테스트를 포함하며, 배포되는 앱 및 SDK의 기기 밖 수집과 제3자 공유를 반영한다. Google의 GMA 공시에서 자동 수집·공유한다고 설명한 항목은 버전과 실제 전송을 대조할 후보로 남긴다. 수탁자 예외는 계약과 지시 범위, 자체 이용 목적을 확인한 뒤 판단한다. 전송 시 암호화는 모든 신고 대상 흐름, 선택 여부는 모든 이용자의 제어 가능성, 일시 처리는 저장·이용 범위를 근거로 답한다. GMA의 최신 TLS 설명을 UMP나 이메일 등 전체에 일반화할 수 없다. 데이터 삭제 요청 제공 여부는 실제로 처리 가능한 범위로 답한다. [Play Data safety](https://support.google.com/googleplay/android-developer/answer/10787469) · [Play User Data](https://support.google.com/googleplay/android-developer/answer/10144311)
- **광고 포함**, **광고 ID**, 대상 연령과 콘텐츠 등급은 Data safety와 별도 문답이다. 최종 후보의 실제 광고 제공 여부를 Play 기준으로 판단한다. SDK·보상형 UI 포함만으로 광고 제공을 확정하거나, 요청 비활성만으로 광고 ID를 사용하지 않는다고 확정할 수 없다. 매니페스트의 AD_ID 선언과 실제 SDK 접근·전송을 대조하고 Play의 문답·검출 결과를 확인한다.
